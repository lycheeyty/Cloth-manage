# 衣橱管理 App 开发计划（v1.0 MVP）

- **依据**：`docs/PRD.md`（v0.1，2026-07-10）
- **目标版本**：v1.0 MVP
- **平台**：iOS 17+，SwiftUI
- **状态**：规划稿

---

## 一、技术选型

| 领域 | 方案 | 说明 |
|---|---|---|
| UI 框架 | SwiftUI | iOS 17+ 起点，配合 `NavigationStack`、`TabView` 实现三 Tab 架构 |
| 数据持久化 | SwiftData | 本地优先存储；模型层抽象 Repository 协议，为 v1.2 云同步预留接口 |
| 图片抠图 | Vision `VNGenerateForegroundInstanceMaskRequest` | 端侧主体分割，iOS 17+，无网络依赖 |
| 相机/相册 | `AVFoundation` + `PhotosUI (PhotosPicker)` | 拍摄单张；相册多选上限 9 张 |
| 图片存储 | 文件系统（沙盒 Documents）+ SwiftData 存路径 | 抠图 PNG 与原图分开存储，支持存储管理页统计与清理 |
| AI 分类 | Mock 服务（协议抽象） | `ClassificationService` 协议 + `MockClassificationService` 实现，v1.1 无缝换云端实现 |
| 登录 | Sign in with Apple（v1.0 必备）| 手机号/微信登录视后端进度放 v1.1 |
| 架构模式 | MVVM + 模块化目录 | Feature 分层：Wardrobe / Capture / Outfit / Profile / Core |

## 一.5、协作模式（2026-07-10 更新）

代码由 Claude 编写并推送到本仓库；用户在 Mac 上用 Xcode 构建运行，反馈效果与报错。原「周」工期估算不再作为排期依据，里程碑仅表示功能交付顺序与依赖关系，进度以 README「当前进度」清单为准。

| 里程碑 | 内容 | 预估工期 |

## 三、里程碑任务分解

### M0 项目基建（1 周）

- [ ] Xcode 工程初始化（iOS 17 deployment target、SwiftUI App 生命周期）
- [ ] 目录结构与模块划分（Features / Core / DesignSystem / Resources）
- [ ] SwiftData 模型定义：
  - `ClothingItem`（id、名称、分类枚举、原图路径、抠图路径、创建时间）
  - `Outfit`（id、名称、场景标签、单品引用数组、封面拼图路径、创建时间）
  - `SceneTag`（预置 + 自定义场景）
- [ ] Repository 层协议（本地实现，预留云同步接口）
- [ ] 三 Tab 导航骨架（衣橱 / 添加 / 我的），中央 Tab 为主操作位样式
- [ ] 设计系统基础：色板（含深色模式）、字体、间距、3:4 卡片组件底座
- [ ] CI（GitHub Actions：build + 单测）、SwiftLint/SwiftFormat

### M1 添加衣服链路（2 周）

- [ ] 相机拍摄页：点击 Tab 2 直接吊起相机，就绪耗时 ≤ 1s；界面内「相册」入口
- [ ] 相册多选上传（PhotosPicker，上限 9 张）
- [ ] 相机/相册权限请求，拒绝后引导文案 + 「去设置」跳转
- [ ] 端侧抠图服务：`VNGenerateForegroundInstanceMaskRequest` 封装，输出透明底 PNG，目标耗时 ≤ 1s
- [ ] 抠图加载态（骨架屏/进度动画）与结果预览页（重新抠图、「保留原图」开关、确认）
- [ ] 抠图失败兜底：保留原图 + toast 提示，不阻断流程
- [ ] 发布页：
  - [ ] 分类选择（8 个预置分类，必选）
  - [ ] Mock AI 预填分类：「AI 已识别」UI + 一键确认/手动修改；低置信度不预填、分类项高亮
  - [ ] 产品名输入（选填）+ Mock 建议名称
  - [ ] 多图逐张确认：顶部缩略滚轮（横滑切换、当前高亮、已确认打勾），全部确认后统一发布
- [ ] 入库后返回瀑布流并定位新卡片（入场动画）
- [ ] 验收：拍摄 → 发布最短路径 ≤ 3 次点击

### M2 衣橱瀑布流（2 周）

- [ ] 双列瀑布流布局，卡片统一 3:4，抠图居中展示
- [ ] 卡片：左上角产品名（单行截断，无名不显示）、右上角「创建组合」入口
- [ ] 顶部区域：标题/概览 + 排序控件 + 横滑分类筛选 Tab（全部/8 分类/组合）
- [ ] 滚动方向显隐顶部（位移 + 透明度过渡，非吸顶）
- [ ] 排序：默认按时间倒序；分类筛选后组内按时间排序
- [ ] 筛选选择持久化（UserDefaults）
- [ ] 衣物详情页：大图、分类、编辑（名称/分类）、删除（含确认）
- [ ] 空状态：插画 + 「添加第一件衣服」按钮跳转 Tab 2
- [ ] 性能：图片懒加载、渐进式占位、缩略图缓存（滚动 60fps）

### M3 创建组合（1.5 周）

- [ ] 多选模式：卡片入口/详情页「加入组合」进入；卡片右上角变勾选框
- [ ] 底部已选缩略图栏（横滑）+ 「下一步」按钮；最少 2 件、上限 8 件校验
- [ ] 组合发布页：固定网格模板自动拼图预览
- [ ] 场景标签：预置 7 类 + 自定义新增；组合名选填（Mock 建议名）
- [ ] 组合实体入库，瀑布流混排展示（3:4 拼图封面 + 场景角标）
- [ ] 分类筛选 Tab「组合」独立视图
- [ ] 组合详情页：拼图、场景标签、单品列表（跳单品详情）、编辑（增删单品/改场景）、删除组合（不删单品）

### M4 个人设置（1 周，可与 M2/M3 并行）

- [ ] 衣橱统计：衣物总数、组合总数、分类分布图（条形/环形，Swift Charts）
- [ ] 存储管理：图片占用统计、清理缓存、图片质量选项（原图/压缩）
- [ ] 账号管理：Sign in with Apple、头像昵称编辑、退出登录、注销账号
- [ ] Mock 订阅页：免费版 vs 会员版权益对比 UI、「订阅」按钮埋点（不接支付）
- [ ] 基础埋点框架（订阅点击意愿等）

### M5 打磨与验收（1.5 周）

- [ ] 性能验收：瀑布流 60fps、抠图 ≤ 1s、相机就绪 ≤ 1s
- [ ] 深色模式全页面适配走查
- [ ] 动画打磨：新卡片入场、顶部显隐过渡、多选交互
- [ ] 合规：权限用途声明（Info.plist 文案）、隐私协议页、注销入口检查
- [ ] 单元测试（抠图服务、Repository、Mock 分类）与 UI 冒烟测试
- [ ] TestFlight 内测分发与问题修复

## 四、验收标准映射（PRD 3.1.4 / 四）

| 指标 | 目标 | 验证方式 |
|---|---|---|
| Tab → 相机就绪 | ≤ 1s | 真机计时（中低端机型如 iPhone SE 3） |
| 端侧抠图耗时 | ≤ 1s | Vision 请求埋点统计 |
| 抠图主观可用率 | ≥ 90% | 100+ 张实拍衣物样本人工评测 |
| 拍摄 → 发布点击数 | ≤ 3 | 交互走查 |
| 瀑布流滚动 | 60fps | Instruments Core Animation |
| 分类识别准确率 | ≥ 85%（v1.1 随真实识别验收） | 暂不验收，Mock 阶段跳过 |

## 五、风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| Vision 分割对复杂背景/多主体效果不稳 | 抠图可用率不达标 | 早期（M1 第 1 周）用真实衣物样本集验证；提供「保留原图」兜底；引导拍摄提示（纯色背景） |
| 瀑布流大图内存/帧率压力 | 滚动卡顿 | 入库时生成缩略图两级缓存；`LazyVGrid` + 按需解码 |
| 多图逐张确认交互复杂 | M1 工期超支 | 先做单图链路打通，多图滚轮作为 M1 内的第二迭代 |
| Sign in with Apple 依赖后端账号体系 | M4 阻塞 | v1.0 可先做本地账号态 + Apple 登录凭证本地校验，服务端账号体系与云同步一并放 v1.2 |
| Mock 与真实 AI 识别切换成本 | v1.1 返工 | 分类/命名建议统一走 `ClassificationService` 协议，UI 不感知实现来源 |

## 六、后续版本预留（不在本计划内实施）

- **v1.1**：云端多模态分类识别（绑定订阅权益）、抠图手动微调、扩展字段（颜色/季节/品牌/价格）、组合自由排版
