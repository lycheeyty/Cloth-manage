# 衣橱管理 App 需求文档（PRD）

- **版本**：v0.1（首版）
- **平台**：iOS（iOS 17+）
- **日期**：2026-07-10
- **状态**：草稿，待评审

---

## 一、产品概述

### 1.1 产品定位

一款极简的个人衣橱管理工具。用户通过拍照或上传将衣物数字化归档，系统自动抠图并识别分类，形成可浏览、可组合的视觉化衣橱。核心价值在于「让整理衣橱像刷图片流一样轻松」，降低录入成本（自动抠图 + AI 分类），提升浏览体验（瀑布流 + 穿搭组合）。

### 1.2 设计原则

- **极简架构**：底部仅三个 Tab，无二级导航迷宫，所有核心操作两步内可达。
- **录入零负担**：拍摄/上传后自动完成抠图与分类识别，用户只需确认，不需手动填写。
- **视觉优先**：衣物以统一比例的抠图卡片呈现，衣橱本身即是一面「视觉墙」。

### 1.3 目标用户

- 衣物数量较多、有整理和搭配需求的个人用户
- 关注穿搭、希望在出行/通勤等场景快速决策「穿什么」的用户

## 二、信息架构

底部 Tab Bar 固定三项：

| Tab | 名称 | 功能定位 |
|---|---|---|
| Tab 1 | 衣橱（瀑布流） | 默认首页，浏览全部衣物，入口：查看详情、创建组合 |
| Tab 2 | 添加 | 中央主操作位，吊起相机拍摄或从相册上传 |
| Tab 3 | 我的 | 衣橱统计、存储管理、账号管理、订阅管理 |

页面层级示意：

```
App
├── Tab1 衣橱瀑布流
│   ├── 衣物详情页
│   ├── 创建组合流程（多选 → 组合发布页）
│   └── 组合详情页
├── Tab2 添加衣服
│   ├── 相机拍摄 / 相册上传
│   ├── 自动抠图预览
│   └── 发布页（分类确认 + 信息编辑）
└── Tab3 个人设置
    ├── 衣橱统计
    ├── 存储管理
    ├── 账号管理
    └── 订阅管理（Mock）
```

## 三、功能需求

### 3.1 添加衣服（Tab 2）

**流程：拍摄/上传 → 自动抠图 → 发布页确认 → 入库**

#### 3.1.1 图片获取

- 点击「添加」Tab 直接吊起系统相机（默认路径），界面内提供「相册」入口切换为上传。
- 支持单张拍摄；相册上传支持多选（建议上限 9 张）。
- **多图确认交互**：逐张确认信息，发布页顶部提供多图缩略滚轮（横向滑动切换），当前编辑图高亮，已确认图打勾标记；全部确认后统一发布入库。
- 权限处理：首次使用时请求相机/相册权限，拒绝后展示引导文案与「去设置」跳转。

#### 3.1.2 自动抠图

- 图片获取后自动执行主体分割，去除背景，输出透明底（PNG）或统一浅色底的衣物图。
- **技术方案：端侧处理**。使用 iOS Vision 框架主体分割（VNGenerateForegroundInstanceMaskRequest，iOS 17+）；无网络依赖，图片不出设备。
- 抠图过程展示加载态（骨架屏或进度动画），端侧处理目标耗时 ≤ 1s。
- 抠图结果预览页支持：重新抠图、手动微调边缘（v1 可降级为「保留原图」开关）、确认进入发布页。
- 抠图失败兜底：保留原图并提示「未能识别主体，已使用原图」，不阻断流程。

#### 3.1.3 发布页（信息确认）

- **分类**：必选项。预置分类：上装、下装、外套、连衣裙、鞋子、包袋、配饰、其他。
  - **AI 自动识别（首版示意 / Mock）**：发布页保留「AI 已识别」的 UI 呈现与交互（预填分类 + 一键确认 / 手动修改），首版不接真实识别服务，预填结果由 Mock 逻辑给出；真实云端识别（多模态模型 API）纳入后续版本，并预留为订阅权益抓手。
  - 交互上保证 Mock 与真实识别可无缝切换：识别置信度低时不预填，分类项高亮提示用户选择。
- **产品名**：文本输入，选填；AI 可基于识别结果生成建议名称（如「白色针织开衫」），用户可编辑。
- **可选扩展字段（v1.1 可迭代）**：颜色、季节、品牌、价格。
- 点击「发布」后入库，返回瀑布流首页并定位到新卡片（带入场动画）。

#### 3.1.4 验收要点

- 从点击 Tab 到相机就绪 ≤ 1s。
- 端侧抠图成功率（主观可用）≥ 90%，耗时 ≤ 1s；分类识别准确率指标（≥ 85%）随真实识别接入版本一并验收。
- 全流程（拍摄 → 发布）最短路径 3 次点击内完成。

### 3.2 衣橱瀑布流（Tab 1）

#### 3.2.1 卡片规格

- 双列瀑布流，卡片统一 **3:4** 比例（宽:高），衣物抠图居中展示。
- **左上角**：产品名（单行截断，无名称则不显示）。
- **右上角**:「创建组合」入口（图标按钮），点击进入多选模式。
- 点击卡片进入衣物详情页（大图、分类、编辑、删除）。

#### 3.2.2 顶部区域与滚动行为

- 顶部区域包含：页面标题/衣橱概览、排序切换控件。
- **滚动时顶部跟随滑走**（非吸顶），最大化浏览面积；下拉回滚时顶部重新出现（建议实现为随滚动方向显隐，带位移+透明度过渡）。

#### 3.2.3 排序与筛选

- **按时间**：默认排序，最新添加在前。
- **按分类**：顶部提供横滑分类筛选 Tab（全部 / 上装 / 下装 / 外套 / 连衣裙 / 鞋子 / 包袋 / 配饰 / 组合），选中某分类后瀑布流仅展示该分类内容，组内按时间排序。
- 分类 Tab 与页面标题同属顶部区域，滚动时一并跟随滑走。
- 筛选选择持久化记忆，下次进入保持上次选择。

#### 3.2.4 空状态

- 无衣物时展示插画空状态 + 「添加第一件衣服」引导按钮，点击跳转 Tab 2。

### 3.3 创建组合（穿搭合集）

**流程：进入多选 → 选中多张 → 组合发布页 → 生成合集**

#### 3.3.1 多选模式

- 入口：瀑布流卡片右上角「创建组合」按钮，或详情页内「加入组合」。
- 进入多选模式后，卡片右上角变为勾选框，底部出现已选缩略图栏（横滑）与「下一步」按钮。
- 至少选择 2 件方可进入发布页；上限建议 8 件。

#### 3.3.2 组合发布页

- 展示所选衣物的组合预览（自动排版拼图，v1 可用固定网格模板）。
- **场景选择**：预置场景标签：上班、度假、约会、运动、日常、聚会、其他（支持自定义新增）。
- 组合名称：选填，AI 可根据场景与单品生成建议名（如「初秋通勤」）。
- 发布后生成「组合」实体，在瀑布流中**与单品卡片混排展示**（同为 3:4 卡片，以拼图封面 + 场景标签角标区分）；分类筛选 Tab 中提供「组合」项可单独查看。

#### 3.3.3 组合详情页

- 展示组合拼图、场景标签、包含的单品列表（点击可跳单品详情）。
- 支持编辑（增删单品、改场景）、删除组合（不删除单品本身）。

### 3.4 个人设置（Tab 3）

#### 3.4.1 衣橱统计

- 顶部展示：衣物总数、组合总数、各分类数量分布（可视化为简单条形/环形图）。

#### 3.4.2 存储管理

- 展示图片占用空间总量。
- 提供操作：清理缓存、图片质量选项（原图/压缩）。

#### 3.4.3 账号管理

- 登录方式：Sign in with Apple（App Store 审核要求，若提供第三方登录则必须包含）+ 手机号，可选微信登录；头像昵称编辑、退出登录、注销账号（合规必备）。

#### 3.4.4 订阅管理（首版 Mock）

- Mock 展示：免费版 vs 会员版权益对比（如衣物数量上限、AI 识别次数、云端同步）。
- 「订阅」按钮首版仅展示 UI，不接入真实支付；埋点记录点击意愿数据。

## 四、非功能需求

- **性能**：瀑布流滚动 60fps，图片懒加载 + 渐进式占位；单图上传后端处理（抠图+识别）总耗时 ≤ 5s。
- **数据**：首版本地优先存储，预留云同步接口（会员权益方向）。
- **平台范围**：首版仅 iOS，最低支持 **iOS 17**（Vision 主体分割 API 要求）；适配深色模式；Android 版本视 iOS 验证结果另行规划。
- **合规**：相机/相册权限用途声明、用户图片隐私协议、账号注销入口。
